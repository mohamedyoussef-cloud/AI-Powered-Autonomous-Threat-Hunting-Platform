# Architecture Decision Log

## ADR-001: Sigma-first detection synthesis

**Decision:** Generate a canonical Sigma rule, validate it, then compile it to SPL/KQL/Elasticsearch-compatible queries using approved backends and mappings.

**Reason:** The later project specification defines Sigma as the shared vendor-neutral detection language and the primary LLM training source. This supersedes the earlier direct-SPL generation diagram.

## ADR-002: Separate source models

**Decision:** ATT&CK, Sigma, telemetry, findings, and ML features have separate schemas connected by identifiers and lineage.

**Reason:** They represent different units and cannot be correctly merged into one table.

## ADR-003: Finding-level ML

**Decision:** Build ML examples from aggregated findings/cases.

**Reason:** BOTS v3 lacks direct labels for every event, and EVTX is attack-oriented. Event-level source labels would create severe bias and leakage.

## ADR-004: DARPA excluded from core

**Decision:** Retain DARPA Transparent Computing as future provenance-graph work only.

**Reason:** Correct use requires a separate graph storage, provenance reconstruction, causal-path analysis, graph features, and evaluation methodology.

## ADR-006 — Use repository-published EVTX CSV with explicit raw-coverage accounting

**Decision:** Use `evtx_data.csv` as the source-native parsed table for the first EVTX normalization pass, while separately inventorying and hashing all raw EVTX files.

**Reason:** The execution environment does not contain `python-evtx`, while the source repository supplies a parsed table generated by its own notebook. The table covers 249 of 278 raw files.

**Constraint:** No events are synthesized for the 29 uncovered files, and complete raw EVTX coverage cannot be claimed until they are directly parsed.


## ADR-008 — BOTS v3 journals require Splunk-supported export

**Decision:** Directly profile bucket metadata and app configuration, but do not treat `rawdata/journal.gz` as generic line-oriented logs. Full event extraction will use a compatible Splunk runtime and bounded REST/SDK exports.

**Reason:** The pre-indexed archive depends on Splunk event boundaries, TSIDX metadata, source typing, and search-time `props.conf`/`transforms.conf`. A custom binary-journal decoder would create avoidable correctness and lineage risk.

## ADR-009 — Separate administrative and disabled-bucket records

**Decision:** Preserve active index count, scenario-telemetry count, administrative content-import records, and disabled bucket records as separate quantities.

**Reason:** Merging them would contaminate scenario timing, feature distributions, and ground-truth construction.
