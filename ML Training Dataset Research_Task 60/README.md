# Task 60: ML Training Dataset Research

## Overview
Research into suitable labeled datasets for training the ML Triage model.
The ML model classifies Splunk findings into:
- 1 = True Positive (real attack)
- 0 = False Positive (benign activity)
- 2 = Needs Review (escalate to SOC analyst)

## What We Analyzed

### Step 1: Analyzed the Fine-Tuned Model Output
We analyzed eval_results.json (394 valid Sigma rules generated by our
fine-tuned model) to understand what types of logs our Sigma rules target:

Original distribution (before filtering):
  166  windows   (42%)
  164  cisco     (41%)  ← model loop artifact
   57  azure     (14%)
    7  other      (2%)

Problem: 41% of outputs were Cisco AAA rules caused by a model
repetition loop — not representative of our intended scope.

### Step 2: Filtered Training Data
We filtered train.jsonl to keep only Windows + Linux + Generic rules:
  Original : 3,770 examples
  Filtered : 3,321 examples (kept)
  Removed  :   449 examples (Cisco, Azure, AWS, macOS)

### Step 3: Analyzed Filtered Categories
After filtering, our Sigma rules target these log categories:

  1684  process_creation    (51%)  ← Windows/Linux process logs
   443  none/generic        (13%)  ← generic detection
   209  file_event          (6%)   ← file system events
   173  ps_script           (5%)   ← PowerShell logs
   154  registry_set        (5%)   ← Windows registry
   132  image_load          (4%)   ← DLL/module loading
    91  network_connection  (3%)   ← network events
    87  webserver           (3%)   ← web server logs
    61  proxy               (2%)   ← proxy logs
    33  dns_query           (1%)   ← DNS logs

## Selected Datasets

### Dataset 1: OTRF Security-Datasets
**Link:** https://github.com/OTRF/Security-Datasets

**What it contains:**
- Simulated attack scenarios mapped to MITRE ATT&CK techniques
- Windows Event Logs (process creation, registry, file events)
- Linux audit logs
- JSON format, ready for processing

**Why we chose it:**
- Covers 51% of our rules (process_creation category)
- Organized by ATT&CK technique = easy to assign labels
- Known attack scenarios = label 1 (True Positive)
- Free and open source

**Covers these categories:**
  process_creation, file_event, registry_set,
  image_load, ps_script, network_connection

**Advantages:**
- ✅ Directly mapped to MITRE ATT&CK
- ✅ Windows + Linux coverage
- ✅ Easy labeling: attack scenarios = label 1
- ✅ Regularly updated
- ✅ Free

**Disadvantages:**
- ❌ No pre-labeled benign/malicious at finding level
- ❌ Requires manual labeling effort
- ❌ Relatively small compared to other datasets

---

### Dataset 2: CICIDS 2017
**Link:** https://www.kaggle.com/datasets/cicdataset/cicids2017
**Official:** https://www.unb.ca/cic/datasets/ids-2017.html

**What it contains:**
- 5 days of network traffic (Monday-Friday)
- Monday: benign traffic only
- Tuesday-Friday: attack traffic (Brute Force, DoS, DDoS,
  Web Attack, Botnet, Port Scan, Infiltration)
- 80+ network flow features extracted by CICFlowMeter
- Pre-labeled: BENIGN / attack type
- Size: ~51 GB (PCAP) + CSV files available

**Why we chose it:**
- Covers network_connection, proxy, dns_query categories
- Pre-labeled = easy to use directly
- Large and diverse attack coverage
- Covers 6% of our Sigma rules (network categories)

**Covers these categories:**
  network_connection, proxy, dns_query, webserver

**Advantages:**
- ✅ Pre-labeled (BENIGN / ATTACK) — ready to use
- ✅ Large dataset (2.8M+ records)
- ✅ Multiple attack types
- ✅ Windows + Linux + Mac machines in environment
- ✅ CSV format — easy to load

**Disadvantages:**
- ❌ Network traffic only (no Windows event logs)
- ❌ Published in 2017 — some attack patterns may be outdated
- ❌ Large size (~51GB PCAP)
- ❌ Not mapped to MITRE ATT&CK

---

### Dataset 3: BETH Dataset
**Link:** https://www.kaggle.com/datasets/katehighnam/beth-dataset

**What it contains:**
- Host-based security events from Linux systems
- Linux audit logs (syscalls, process events)
- Pre-labeled: benign / malicious
- 8 million+ events
- Published 2021 — more recent than CICIDS

**Why we chose it:**
- Covers Linux-specific Sigma rules (196 Linux rules in training data)
- Pre-labeled at event level
- Host-based = matches process_creation and file_event categories
- More recent dataset

**Covers these categories:**
  process_creation (Linux), file_event (Linux),
  ps_script (Linux), network_connection (Linux)

**Advantages:**
- ✅ Pre-labeled (benign/malicious)
- ✅ Large (8M+ events)
- ✅ Recent (2021)
- ✅ Linux host-based = matches our Linux Sigma rules
- ✅ Designed specifically for ML security research

**Disadvantages:**
- ❌ Linux only (no Windows coverage)
- ❌ Not mapped to MITRE ATT&CK
- ❌ Syscall-level events may need transformation

## Labeling Strategy
Since ML model needs finding-level labels (TP/FP/NR):


OTRF  → known attack scenarios  = label 1 (True Positive)
OTRF  → normal activity         = label 0 (False Positive)
CICIDS → BENIGN traffic          = label 0 (False Positive)
CICIDS → attack traffic          = label 1 (True Positive)
BETH  → benign events            = label 0 (False Positive)
BETH  → malicious events         = label 1 (True Positive)


Ambiguous findings → label 2 (Needs Review / Escalate to SOC)
